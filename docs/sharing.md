# 项目说明与发布要求

## 项目定位

用户准备 VPS、Cloudflare 域名和 AI 的工具授权，由 AI 查询参数、填写配置、执行部署、排错和验证。服务器负责自动续期、巡检和备份。

## 使用流程

1. **准备资源与授权。** 提供目标 VPS 与域名，由 AI 检查工具、SSH 登录、可信主机指纹、Cloudflare 授权和续期凭据。
2. **提交部署任务。** 使用 README 中的任务说明，由 AI 查询参数并填写配置。密码和 Token 通过安全入口提供，不进入聊天或工具记录。
3. **检查部署条件。** AI 执行 `plan`、`preflight`；发现已有业务、DNS 冲突或权限缺失时，说明具体问题与处理方式。
4. **部署并验证。** AI 执行 `deploy`、`status` 与 `verify`，核对服务端状态及三条线路的实际出口，不公开客户端文件正文。
5. **配置客户端。** AI 尽可能完成导入，用户处理必要的系统授权。分别确认 TUN、出口和 DNS 检查结果。
6. **持续维护。** VPS 执行定时巡检、续期和备份；AI 按需排错、升级和回滚。升级前备份，完成后重新验证。

## 公开内容范围

- 本仓库源码、示例参数、架构说明、测试方法。
- 脱敏后的计划与健康报告。实际 IP 和域名是否公开，由资源所有者决定。
- 已完成与未完成的验收证据；未经实测不得承诺全流程成功。

## 发布步骤

1. 在全新测试 VPS 和独立测试 Zone 完成一次完整验收，记录成本、耗时和版本。
2. 运行单元测试、公开文件检查；检查 `git diff --cached`，确认没有真实配置、artifacts、私钥、Token 或备份。
3. 首次发布时，在选定的 Git 托管平台创建空仓库，添加 remote 后 push；已有远端则核对目标后发布更新。此步骤由仓库所有者执行或明确授权 AI。
4. 以公开仓库 URL 和 README 作为使用入口。不要复制上一级私人运维资料到此仓库。

## 常见问题

**需要自己敲命令或填配置吗？** 工具和授权就绪后由 AI 执行。用户只处理工具无法代办的登录、秘密输入及系统权限；AI 应明确指出最小操作，而不是把整份手册交还给用户。

**只有 VPS 密码和 Cloudflare MCP 就够了吗？** 当前脚本还需要公钥登录和专用 API Token。AI 可以在具备安全交互能力时准备公钥，并检查凭据准备路径；不能把 MCP OAuth 当作服务器自动续期凭据。参见 [环境准备](ai-environment.md)，首次使用流程尚待端到端实测。

**需要 AI 一直开着吗？** 不需要。服务、续期和定时维护在 VPS 上运行；需要诊断或变更时再让 AI 操作。

**会自动升级所有软件吗？** 不会。无人值守只处理证书、巡检和备份，版本迁移与系统重启需要具体维护任务。

**买了资源就一定能用吗？** 云安全组、线路质量、UDP 限制、Cloudflare 规则、客户端兼容性都会影响结果，所以交付包含真实协议验收。

**能直接接管以前搭好的服务吗？** 首版拒绝接管未知部署，避免覆盖已有业务。
