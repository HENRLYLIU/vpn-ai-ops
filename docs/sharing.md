# VPN 搭建分享：讲稿与演示

## 一句话介绍

“你提供 VPS 和 Cloudflare 域名，AI 使用一个可审查的 Git 仓库完成搭建；服务器负责自动续期、巡检和备份，AI 帮你排错、升级和回滚。”

## 15 分钟演示顺序

1. **2 分钟：资源与架构。** 展示三线路图，说明 vpn 直连、ws 经 Cloudflare，确认 Ubuntu 和 SSH 前提。
2. **2 分钟：AI 入口。** 打开 README，把部署提示词交给 AI。只展示示例配置；Token 在屏幕外安全输入。
3. **3 分钟：可审查的计划。** 演示 `plan`、`preflight`，解释已有业务和 DNS 冲突时为何停止。
4. **4 分钟：部署与验证。** 运行 `deploy`（网络耗时不计入讲解），展示脱敏输出和三个协议验证结果，不打开客户端文件正文。
5. **2 分钟：导入客户端。** 私下导入配置，打开 TUN，展示出口和 DNS 检查结论。录屏遮挡链接、二维码、凭据。
6. **2 分钟：维护。** 展示 timer、`status`、备份名；说明升级先备份，失败回滚。不要为了演示在真实服务上随意升版本。

## 可以分享的内容

- 本仓库源码、示例参数、架构图、测试方法。
- 脱敏后的计划与健康报告。实际 IP/域名虽非密码，也先按分享范围决定是否展示。
- 已完成/未完成的验收证据，而不是未经实测的“全自动成功”承诺。

## 发布步骤

1. 在全新测试 VPS 和独立测试 Zone 做一次完整验收，记录成本、耗时和版本。
2. 运行单元测试、公开文件检查；检查 `git diff --cached`，确认没有真实配置、artifacts、私钥、Token 或备份。
3. 在你选择的 Git 托管平台创建空仓库，添加 remote 后 push。此步骤由仓库所有者执行或明确授权 AI。
4. 将公开仓库 URL 和 README 入口放进分享材料。不要复制上一级私人运维资料到此仓库。

## 常见问答

**需要 AI 一直开着吗？** 不需要。服务、续期和定时维护在 VPS 上运行；需要诊断或变更时再让 AI 操作。

**会自动升级所有软件吗？** 不会。无人值守只处理证书、巡检和备份，版本迁移与系统重启需要具体维护任务。

**买了资源就一定能用吗？** 云安全组、线路质量、UDP 限制、Cloudflare 规则、客户端兼容性都会影响结果，所以交付包含真实协议验收。

**能直接接管以前搭好的服务吗？** 首版拒绝接管未知部署，避免覆盖已有业务。
