# 先让 AI 准备好实施环境

这份清单主要给执行 AI 阅读。目标是让用户完成资源准备和授权后，部署过程由 AI 持续执行。用户不必理解 Zone ID、环境变量或配置格式。

## 用户提供，AI 检查

用户提供 VPS 公网 IP、SSH 用户名与端口、Cloudflare 域名和客户端设备类型。首次密码或已有私钥只能通过安全工具入口、SSH Agent 或文件路径提供。证书联系邮箱优先使用用户明确指定的地址，缺少时一次询问；不擅自使用 MCP 账号邮箱。

AI 先核实以下能力，输出“可用 / 缺少 / 待用户授权”及下一步，不输出任何凭据：

| 能力 | AI 应做的检查 | 不具备时的最小动作 |
| --- | --- | --- |
| 本地终端与网络 | 确认实际执行环境、Python 3.10+、OpenSSH、Git、curl；在已有授权范围内补齐依赖 | 请求必要的安装或管理员授权 |
| SSH 登录与可信主机身份 | 验证公钥或安全交互登录渠道，取得云控制台等可信来源的主机指纹 | 用户通过控制台取得指纹或完成一次可信首次登录 |
| 秘密传递 | 确认密码/Token 能进入实际执行进程，且不回显、不进入工具日志或聊天 | 使用工具支持的安全输入/秘密存储；没有这类渠道就停在凭据准备，不索取聊天明文 |
| Cloudflare 资源访问 | 检查 API MCP 的实际连接、账号、域名和读写范围 | 用户完成浏览器登录及对应授权 |
| 脚本与续期凭据 | 验证部署进程能使用限定到该域名的 API Token，而不是只看到 MCP 已登录 | 按下文准备一次专用 Token |
| 云端网络 | 检查实际 SSH、443 TCP/UDP、8443 TCP 的放行条件 | 有云厂商工具则在授权范围内配置；没有则请用户只完成对应安全组规则 |
| 客户端控制 | 检查官方客户端/核心、桌面或设备控制能力 | 用户只处理无法代办的安装、导入或系统权限弹窗 |

本地 AI 的普通聊天窗口不等于安全输入通道。另一个终端里 export 的变量，也不会自动进入 AI 的独立进程。

## VPS 只有密码时

现有 `vpnctl.py` 使用 `BatchMode=yes`，不接受交互式密码。首次接入由 AI 的终端/SSH 工具完成，然后交给现有脚本：

1. 从可信控制台取得并核验主机指纹；不通过关闭主机校验来跳过此步。
2. 若工具支持不记录秘密的交互登录，让用户在该入口输入一次密码。
3. 使用已有合适公钥，或在本地受限位置生成专用密钥；向目标账户追加公钥，保留已有 `authorized_keys` 内容。
4. 开一个独立连接，验证公钥登录。非 root 账户还需验证 `sudo -n true`；不通过本流程擅自扩大 sudo 权限。
5. 验证成功后使用 SSH Agent 或私钥路径运行项目。保留恢复渠道，不修改 sshd、不关闭原密码登录。

若环境只能执行非交互命令，又没有安全的凭据传递工具，AI 应明确说明缺少这一能力，指导用户只完成首次公钥接入。不能把密码写入命令参数、配置文件、临时脚本或聊天来凑通流程。仅在用户提供的是全新或本项目已受管 VPS 时继续部署；旧业务使用单独迁移方案。

## Cloudflare MCP 如何准备

使用支持资源操作的 **Cloudflare API MCP**，官方地址为 `https://mcp.cloudflare.com/mcp`。只查文档的 MCP 不能代替它。AI 按所用客户端的当前官方说明协助接入；用户在浏览器中完成 Cloudflare 登录与权限选择。[官方接入说明](https://github.com/cloudflare/mcp/blob/main/README.md)

AI 实际调用只读操作，确认连接的账号与域名、Zone 状态、现有 DNS 和 SSL/TLS 设置。仅针对本项目域名请求所需权限，不能因为工具连接成功就假定全部 API 可用。

- MCP 可用于查询 Zone ID、检查解析及设置，并在权限允许时操作 DNS。
- 当前 CLI **不会直接调用 MCP**，`preflight` 和 `deploy` 仍会使用 `CF_API_TOKEN` 调用 Cloudflare API。因此即使 MCP 已准备好 DNS，也不能跳过 Token 或脚本预检。
- DNS 创建默认交给 `deploy` 完成，避免重复实施。MCP 已创建的记录必须与项目期望完全匹配，否则按冲突处理。
- 当前脚本只读检查 `Full (strict)`。独立、无其他业务的测试 Zone，可由有权限的 AI 在已说明范围内配置；共享 Zone 的设置变更需先评估影响并取得明确同意，不为通过预检直接修改。
- 该 MCP 不提供 VPS 云厂商账号权限；云安全组需要独立工具或一次控制台操作。

MCP 不是当前脚本的运行依赖。没有 MCP 但已提供有效 Token 时，现有 CLI 仍可运行；若 Zone ID 尚不清楚，AI 可通过权限允许的 API 查询。无需为安装 MCP 而阻塞已有可用的凭据路径。

## 为什么还需要专用续期凭据

MCP OAuth 让当前 AI 能访问 Cloudflare；VPS 上的 acme.sh 在本地电脑关闭后仍需独立调用 DNS API。当前实现使用 API Token 完成正式证书签发与续期。

由 AI 按顺序选择：

1. **已有安全存储的 Token**：将其注入实际部署进程的 `CF_API_TOKEN`，只检查存在性和操作结果，不读取值到对话。
2. **工具允许安全创建并交付 Token**：先确认实际权限和工具文档，再创建限定到该域名的凭据。必须支持秘密直接进入安全存储/进程、返回结果仅含引用或脱敏状态。会把 Token 正文返回到聊天或工具记录的路径不满足要求。
3. **不具备上述能力**：让用户按 [Token 指南](cloudflare-token.md) 完成一次创建，并使用本地安全输入入口交付。AI 解释需要点击的具体选项，不要求用户理解和填写配置文件。

所需权限为目标 Zone 的 DNS Edit、Zone Read、Zone Settings Read。不能假定 MCP OAuth 已授权 Token 创建，也不提取或复制 AI 工具的 OAuth 会话凭据给 VPS。

脚本会通过 SSH 将 Token 交给 acme.sh，保存在 VPS 的受限目录，以支持后续自动续期。部署后清理本地临时环境变量；不要删除服务器续期所需凭据。存在有效期或来源 IP 限制时，AI 应检查本地执行环境与 VPS 是否都能使用，并记录到期提醒但不记录秘密。

## 准备完成的判断

当 AI 已能执行本地命令、通过可信公钥登录目标、使用受限 Token 检查正确 Zone，并确认网络条件后，进入 [部署提示词](../prompts/deploy.md)。只有 MCP 登录成功或密码已提供，不能报告“部署环境已就绪”。

缺少某项时，说明“我已完成什么；还缺哪个权限/工具；请你完成哪一个动作；之后我会继续什么”。不要把后续部署步骤整份交给用户手动执行。
