# 设计

遵循 `.agent/adr/001-agent-first.md`：AI 负责资源理解和工具编排，现有脚本承担重复执行，服务器承担无人值守维护。

## 已确认方向

用户已确认“先准备环境与工具，实施交给 AI”。本次以文档交付这一流程，不扩展部署代码。README 面向用户，`docs/ai-environment.md` 面向首次环境准备，`docs/setup.md` 和 `prompts/deploy.md` 面向执行 AI。

## 流程

1. 用户准备受支持的新 VPS、Cloudflare 域名、本地 AI；在安全入口提供登录凭据并完成工具授权。
2. AI 检查终端、网络、SSH、秘密传递、Cloudflare API MCP 及可选的云厂商/设备工具；只报告可用状态，不读取秘密到对话。
3. AI 查询可发现参数，生成默认子域名与配置。密码引导只在已有安全交互能力下进行，主机指纹需可信来源；建立并验证公钥登录后才调用现有 CLI。
4. MCP 用于发现与权限允许的资源操作；当前 CLI 的 DNS 检查和证书续期仍需要 `CF_API_TOKEN`。无安全凭据创建/传递能力时让用户完成一次受限 Token 准备，不提取 MCP 的 OAuth 会话。
5. 现有 plan/preflight/deploy/status/verify 路径保持不变。共享 Zone 设置、已有业务冲突、无法操作的安全组作为明确边界处理。
6. AI 自动完成能执行的客户端配置和验证；用户处理登录、验证码及操作系统授权。

## 影响与回退

更新 README、AGENTS 运维段、环境/参数/运维/发布/测试文档及部署提示词。Token 指南保留为首次授权的备用说明。无生产操作与运行时修改；可通过恢复本次文档差异回退。
