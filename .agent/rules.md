# Rules

## 开发限制

禁止扫描或修改：

* node_modules
* dist
* build
* target
* unpackage
* .git
* .next
* .nuxt
* coverage
* .venv

除非用户明确要求。

---

## 范围限制

禁止无目的全文扫描项目。

优先分析：

1. 当前 Spec 相关文件
2. 最近修改文件
3. 直接依赖模块
4. 配置文件
5. 测试文件

只有在必要时才扩大分析范围。

---

## 修改限制

优先最小修改。

禁止：

* 大规模重构
* 修改无关模块
* 批量格式化整个项目
* 修改未分析文件

除非用户明确要求。

---

## 协作规则

遇到新功能、产品设计、页面设计、信息架构、交互体验、架构方案或长期流程调整时，必须先让用户参与方向确认。

进入实现前必须先给出：

1. 需求理解
2. 关键选择点
3. 2-3 个可选方案
4. 推荐方案及原因
5. 需要用户确认的问题

用户确认前，不得直接 finalize Design、拆最终 Tasks 或进入实现。

如果用户明确要求直接实现，或需求是低风险且边界清晰的轻量修改，可以直接推进，但必须说明关键假设。

第一版实现完成后，应先交给用户验收，再继续做体验细化、内容扩展或额外优化。

---

## 安全规则

禁止硬编码：

* 用户名
* 密码
* API Key
* Token
* Secret
* Cookie
* Access Key
* Private Key

必须使用环境变量、配置文件或 Secret Manager。

禁止提交：

* .env
* .env.local
* *.pem
* *.key
* credentials/
* secrets/

新增环境变量时，同步更新 `.env.example`，仅写占位符，禁止写真实值。

---

## 验证规则

关键修改后必须执行：

* 类型检查
* 编译检查
* 测试验证

无法验证时必须说明原因。
